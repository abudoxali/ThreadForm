# ThreadForm Garment QA

A real inspect-fix-reinspect loop against the actual files, not a checklist
recited from memory. Every check below names the exact command/tool that
performs it — don't claim a check passed without running it.

## 1. Manifest validation (schema boundary)

- Confirm `assets/garments/<id>/manifest.json` and its served copy under
  `apps/web/public/garments/<id>/manifest.json` are byte-identical (the
  generator script is supposed to keep them in sync — diff them).
- Run the manifest through `packages/garment-runtime`'s
  `garmentManifestSchema` (e.g. a throwaway `node -e` / vitest snippet
  importing `loadManifest` or the schema directly) — don't eyeball the JSON
  against the zod shape by hand.
- Confirm `garmentId`/`slug` match the directory name, `model.reference`
  points at a file that actually exists, and `cameraPresets` only lists ids
  that exist in `packages/garment-runtime`'s `CAMERA_PRESETS`.

## 2. GLB inspection (actual geometry, not assumed)

Use `scripts/verify-essential-tee.mjs` as the template — adapt its garment
id/path for a new asset, or generalize it if there's now more than one
garment. It loads the raw GLB via `GLTFLoader.parse()` (no fetch/DOM needed)
and reports, per mesh: vertex/triangle count, presence of `normal` and `uv`
attributes, and material name — plus overall bounds size/center and file
size. Run it and check:

- Mesh names match `manifest.model.meshNaming` exactly (front/back/sleeves)
  — a mismatch here silently breaks print-zone-to-mesh mapping later.
- Every mesh has normals and UVs. Missing normals means flat/broken shading;
  missing UVs blocks any future texture/artwork work even though it's out of
  scope today.
- Triangle count is sane for a development-grade asset (low hundreds to a
  few thousand — flag anything that looks like an accidental
  high-poly/production import).
- Bounds are centered near the origin, right-side-up, and human-garment
  scale in meters (roughly 0.3–1.5m per axis for wearables) — a garment
  off-center or 100x too large/small will frame wrong in `frameGarment`.
- No duplicate/orphaned materials, no baked-in cameras, lights, or
  animations riding along in the export (procedural generators can leak
  these in if the exporter is handed a full scene instead of a targeted
  group).
- File size is reasonable for a development-grade mesh (tens of KB, not
  MB) — flag anything surprising.

## 3. Provenance and licensing

- `PROVENANCE.md` exists next to the asset and states: how it was made
  (procedural script, third-party license, scan, etc.), who created it, its
  `readiness` (must match the manifest's `readiness` field), and any known
  limitations.
- `manifest.provenance.source` is `'threadform-original'` only if the asset
  is genuinely original — never label a copied/scraped/competitor-derived
  asset this way. `'third-party-licensed'` requires the actual license terms
  recorded, not just a source name.
- If the asset was generated by a script (e.g.
  `scripts/generate-essential-tee.mjs`), confirm the script is committed and
  the regeneration command is documented in `PROVENANCE.md` — a garment that
  can't be regenerated from source isn't really provenance-documented.

## 4. Rendered inspection (the part a schema can't catch)

Start the app (`pnpm dev` or a production build) and actually open `/studio`
with this garment selected, using Playwright or an available browser tool —
not reasoning about the mesh in the abstract. Check:

- Silhouette reads as the intended garment category at a glance.
- No Z-fighting, inverted normals (dark/flipped-looking faces), or visible
  seams between separately-authored meshes (e.g. sleeve-to-torso join).
- The garment is fully framed (not clipped) at every camera preset in
  `manifest.cameraPresets`, per `frameGarment`'s bounding-sphere math.
- Changing the color swatch actually changes the rendered material color
  (visually, in the screenshot — not just the UI state).
- No console/WebGL errors while loading or orbiting.

## 5. Fix and re-check

If anything above fails, fix it at the source (regenerate the mesh, correct
the manifest, rewrite `PROVENANCE.md`) and re-run the specific check that
failed — don't just patch the symptom (e.g. don't hand-edit bounds in the
manifest to paper over a mis-centered mesh).

## 6. Report honestly

State exactly which of the above were actually run (name the command/tool),
what passed, what was fixed, and what — if anything — is a known,
deliberately-deferred limitation (e.g. "front and back print zones share one
mesh, so they can't yet be textured independently"). Never claim a rendered
visual check happened if no browser/screenshot tool was actually used.
